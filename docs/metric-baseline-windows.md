# Metric baseline: Windows - 2026-08-28T07:50:13-0400

**The tracked baseline for the Windows bench.** Regenerate with

    python3 tools/flash.py --bin build/baremetal_bringup.bin
    python3 tools/metrics.py --repeats 9 --seconds 3 \
        --out docs/metric-baseline-windows.md

and commit the change, so a moved figure shows up as a diff rather than
as a memory. Every generation is appended to `records/metrics.jsonl`;
this file is the latest one, rendered. `--out` overwrites, so this block
is re-added by hand - true of the macOS baselines as well.

**The counterpart to `docs/metric-baseline-macos.md`, split per host on
purpose.** The USB stacks are not the same instrument: `usbser.sys`
paces the writer where macOS builds a backlog and discards it, which is
worth 1.4-2.2% of the playback ladder at RC 44 and RC 39 there and
0.01% here. A merged baseline would have to call one of those the
figure. Issue #12.

**Taken at `--repeats 9`, and the macOS files' `--repeats 3` is not
enough on this bench.** Three rounds here published `effective_bits`
10.152 with a spread of 0.380; three separate 9-round sessions then
agreed to 0.0014 bits. A 9-sample range cannot be 55x smaller than a
3-sample range from the same distribution, so the short run was
contaminated rather than imprecise - `spectral_lines` read 6 with a
spread of 7 there. Lines depress `effective_bits`, which is the
direction the error went.

Two figures below must not be read at face value:

- **The ladder's deficit is a constant, not a rate.** 512 B appears at
  RC 65 and above while the transfer grows 3.6 MB to 8.4 MB underneath
  it. A fixed byte count independent of transfer size is a tail that is
  not counted, not rate-dependent loss, and it is a different mechanism
  from the macOS rows this file exists to separate.
- **`rise_10_90_ns` is quantized, and the quantum is one tick of
  `TC_CLOCK_HZ` = 39 MHz, or 25.641 ns.** 923.077 ns is 36 ticks. Two
  benches agreeing to three decimals means they landed on the same
  integer tick, not that they agree to a picosecond - but the grid is
  fine enough to separate the tracks, which read 36 and 38 ticks on
  this board.

**The cross-bench gap is not quotable from this file yet.** It is taken
on `99980e5`, and `docs/metric-baseline-macos.md` is nine commits behind
that - the shared console and the shared load monitor both landed in
between, and `effective_bits` here moved 0.166 bits across that change
alone. The two benches need the same commit before the difference
between them means anything.
