# Metric baseline: Windows - 2026-08-27T21:21:25-0400

**The tracked baseline for the Windows bench.** Regenerate with
`python3 tools/metrics.py --repeats 3 --seconds 3 --out
docs/metric-baseline-windows.md`, and commit the change so a moved
figure shows up as a diff rather than as a memory. The machine-readable
run of every generation is appended to `records/metrics.jsonl`; this
file is the latest one, rendered. Note that `--out` overwrites, so this
block is re-added by hand - the same is true of the macOS files.

**The counterpart to `docs/metric-baseline-macos.md`, and it is split
per host on purpose.** The USB stacks are not the same instrument:
`usbser.sys` paces the writer where macOS builds a backlog and discards
it, which is worth 1.4-2.2% of the playback ladder at two rates there
and 0.01% here. A merged baseline would have to call one of those the
figure. Issue #12.

Two things in this run must not be read at face value:

- **Every figure in "Effective resolution and noise" carries a spread
  5-7x the macOS bench's** (0.380 against 0.060 on `effective_bits`).
  The cross-bench gap below is therefore not a settled number - see the
  note in issue #12.
- **`rise_10_90_ns` agreeing with macOS to three decimals is
  quantization, not agreement.** The equivalent-time grid is 1/13 MHz =
  76.923 ns and both benches landed on exactly 12 steps, so the metric
  cannot resolve a difference smaller than +-8%.

Generated by `tools/metrics.py`. Every figure below is qualified by the
conditions in this block; a figure quoted without them is not a figure.
