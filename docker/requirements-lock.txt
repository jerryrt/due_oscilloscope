# The Python environment the image installs, pinned to exact versions
# and to the sha256 of every artifact. Installed with --require-hashes,
# so a resolution that drifts fails the build instead of producing a
# different image from the same Dockerfile.
#
# WHY THIS FILE EXISTS RATHER THAN requirements-dev.txt DIRECTLY.
# That file is the project's declaration and says `pytest>=7.0`, which
# is a floor and not a pin: it states what the suite needs of a bench,
# and a bench is entitled to whatever pytest it has. An image cannot
# live on a floor - "same Dockerfile" would stop meaning "same image"
# the next time pytest releases - so the floor is resolved once, here,
# and the resolution is the thing that is pinned. requirements-dev.txt
# keeps its meaning for benches unchanged.
#
# Transitive dependencies are listed too, because --require-hashes
# refuses a requirement it cannot name. So this is the whole closure,
# not just the four direct lines.
#
# TO REGENERATE, when requirements-dev.txt changes or a pin is bumped:
# resolve it in the base image and hash what pip fetched.
#
#     docker run --rm -v "$PWD/requirements-dev.txt:/req.txt:ro" \
#         ubuntu@sha256:<the digest in the Dockerfile> bash -c '
#         apt-get update -qq && apt-get install -y --no-install-recommends \
#             python3-venv ca-certificates >/dev/null &&
#         python3 -m venv /v && /v/bin/pip install -q -r /req.txt &&
#         /v/bin/pip freeze > /f.txt &&
#         /v/bin/pip download -q --no-deps -r /f.txt -d /d &&
#         cd /d && sha256sum *'
#
# Resolve in the base image, not on a bench: the wheel a bench picks is
# chosen for its own interpreter and platform, and this image is
# CPython 3.12 on linux-x86_64.
