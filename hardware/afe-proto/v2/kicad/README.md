# AFE version 2: the KiCad schematic

KiCad 10.x only (`kicad-cli` 10.0.8 is what generated and checked it). Schematic only: no PCB yet.
Pattern and code are version 1's, now the shared `pcbtools` package.

| file | what |
|---|---|
| `design.py` | the design as data: every part, value, LCSC number, footprint and pin's net; the Due header allocation. The source `pcbtools` generates and checks from |
| `afe-v2.kicad_sch`, `afe-v2.kicad_pro`, `sym-lib-table`, `fp-lib-table`, `lib/afe.kicad_sym` | generated by `pcbtools` from `design.py` (the TPH2502 and ADS1115 symbols are in the project library) |
| `lib/afe.pretty/` | the BNC and Due XIO socket footprints, copied from version 1, kept by hand |

The generator, the checks and the SPICE netlist comparison are version-independent code in `../../pcbtools` (`schematic.py`,
`schematic_rows.py`, `spicecmp.py`) with version 2's data and rows in `pcbtools/boards/v2_sch.py` and `v2_checks.py`; the old
`build_sch.py`, `check.py`, `spicecmp.py` and `sexpr.py` are gone. Run from `hardware/afe-proto`, in the pcb venv or the image:

```sh
python -m pcbtools.boards.v2_checks --build OUT          # writes the project into OUT, then kicad-cli sch upgrade
python -m pcbtools.boards.v2_checks                      # the rows, on a copy of this folder (a few seconds)
python -m pcbtools.boards.v2_checks --arms               # the rows, then the 24 mutation arms (about 45 s)
docker/pcb/run.sh -m 3G -t 300 bash -c 'cd hardware/afe-proto && python3 -m pcbtools.boards.v2_checks --arms'     # the same in the pinned image, from the repository root
```

An arm counts as caught only when a row goes from PASS on the regenerated unchanged project to FAIL on the changed one; a row that
already fails on the clean board makes its arm `NOT TESTABLE`, which fails the `M*` row. The generated header comment now names
`pcbtools.schematic` (this folder's committed schematic still carries the old script's name until it is regenerated), and **the
committed `afe-v2.kicad_pro` is stale**: its ERC exclusion is keyed on the pin uuid of `U3` pin 1, the part's name before the
renumbering to `U401`, so `S1` fails on this folder as it stands and passes on a regenerated one (regenerate it).

The schematic is flat, one sheet, a net label on every pin, laid out by block (power, scope, AWG, calibration,
Due headers). It is a connection list for the netlist and the checks, not a drawing to read for signal flow.
Footprints come from KiCad's standard libraries (0603, 0805, 1206, SOT-23, SOIC-8 3.9 mm for the SOP-8 dual,
MSOP-10, WSON-12) plus `afe.pretty`.

## What it holds

101 parts (79 fitted by the board house), 50 nets. **Designators follow LR-11: the hundreds digit is the block**, and
each part's `block` field in `design.py` says the same (`D1` and `D2` check it):

| block field | range | holds |
|---|---|---|
| CH1 | 1xx | CH1 chain R101-R108, C101-C103, D101, BNC J101, test point TP101 (A1), and **U101, the TPH2502 dual both channels share, with its two supply capacitors C104, C105**: the shared dual takes the 1xx number |
| CH2 | 2xx | CH2 chain R201-R208, C201-C203, D201, BNC J201, TP201 (A0) |
| AWG | 3xx | U301, R301-R309, C301, C303-C306, BNC J301, TP301 (AWG_OUT) |
| POWER | 4xx | LM27762 U401, R401-R405 feedback, R406 5 V sense, R407 bleed, C401-C409, TP401-TP404 (+3V3A, VNEG, +5V_F, GND) |
| REFCAL | 5xx | REF3030E U501 with C501 C502, ADS1115 U502 with C503, ladder R501-R506, sense divider R507-R511, CAL header J501, TP501 (VREF); the loose shunt is SH501 (hand-fitted, no symbol) |
| EDGE | 6xx | Due pass-through headers J601-J607 (POWER0, ADCL0, ADCH0, PWMH0, XIO0, PWML0, COMMUNICATION0), the I2C pull-ups R601 R602, the AREF link R603 (unfitted), the two 0R bridges BR601 BR602, standoffs MH601 MH602 |

Each part's `Sim` field is its name in the studies (`scope.R1a`, `awg.R3`, `pc.R_FB1`). Old-to-new designators of the
first revision: U1 C1 C2 became U101 C104 C105; J1 J2 J3 became J101 J201 J301; U2 U301; U3 U401; U4 U501; U5 U502;
C410 C501; C411 C502; C412 C503; R408 R409 R410 became R601 R602 R603; the Due headers
J4 J601, J5 J602, J6 J603, J7 J606, J8 J607, J9 J604, J10 J605; J11 J501; MH1 MH2 MH601 MH602; TP1..TP6 were replaced
by the eight test points below. Everything else kept its number.

**Test points** (`TestPoint_Pad_D1.5mm`, a plain 1.5 mm top pad, unfitted; print the label at 0.8 mm): TP101 `A1`, TP201
`A0`, TP301 `AWG_OUT` (the stage output net `AWG_VO`, before the back-termination), TP401 `+3V3A`, TP402 `VNEG`, TP403
`+5V_F` (the LM27762's filtered 5 V feed, after the sense resistor R406), TP404 `GND`, TP501 `VREF`.

**Bridges (placeholders until the layout names the nets).** BR601 joins `+3V3A` and `+3V3A_U` (the scope dual's V+ pad and
C104, C105 sit on `+3V3A_U`); BR602 joins `CH2_RISO` (Riso R208's output) and `A0` (the Due pin, TP201, the clamp D201).
Both are Basic 0R 0603 (C21189), in block 6xx because they serve no single block. The netlist comparison treats a
`BR` part as a short (merging the two segment names) and fails if a bridge is not 0 ohm; the layout agent should tell
me which nets the bridges really split and only `design.py` changes.

Due header allocation (V03, `docs/due-header-table.md`): POWER0 5 V and ground; ADCL0 A0 (CH2), A1 (CH1), the ladder
taps on A2..A7 with the reference on A7's pin; ADCH0 DAC0; PWMH0 ground, AREF (through an unfitted 0R, PA-7),
**SDA1 and SCL1 (pins 9, 10: the SAM3X's TWI0; TWI1 is D20/D21, which have the Due's 1.5k pull-ups) for the ADS1115's I2C**;
XIO0 ground. Every other pin is declared NC and passes through. No Due 3.3 V pin is used. D5..D9, D16, D39 are free.

`block_of_parts()` in `pcbtools/boards/v2_checks.py` returns ref -> block for the layout's containment check; `KEY_PARTS` there is the
independent list each block must hold exactly.

## Checks

Run by `python -m pcbtools.boards.v2_checks`; the rows keep their old ids and text.

`S1` ERC (one exclusion, the LM27762 PGOOD tied to ground). `S2` netlist equals `design.py`. `S3` fields equal
`design.py`. `E1` every pin connected or declared NC. `E2` no single-pin net. `E3` value, footprint (exists in a
library), LCSC on every fitted part. `E4` TPH2502, ADS1115, LM27762 pin names against datasheet tables. `B1` value,
LCSC and quantity against the three `parts.csv`, and every row placed. `N1`, `N2` the scope and AWG blocks against
`sim/scope/scope_v2.cir` and `sim/awg/awg.cir`. `C1` rails computed from the netlist (+3.318 V, -2.003 V). `C2`
ladder. `C3` sense divider and ADS1115 pair. `C4` the CAL header and the shunt on the hand-fitted list. `C5` no scope part on the negative rail.
`D1` hundreds digit equals the block, `D2` each block holds exactly its key part list. `H1` Due headers equal the header-pin table.

### The netlist comparison (`pcbtools/spicecmp.py`, rules in `pcbtools/boards/v2_checks.py`)

It compares topology and values, not names. The SPICE side drops the elements listed in `RULES` (sources, rail and
reference models, strays, loads, each with its reason), shorts the 0 V ammeters, collapses a capacitor with its
ESR, and every SPICE element not listed stays in the graph (so a new element fails; a rule naming a vanished element
fails too). The schematic side takes the block's parts from KiCad's exported netlist, expands the BAV99 into two
diodes and the dual into two amplifiers (from pin names), and both sides fold parallel resistors and capacitors.
Then a colour refinement over the element/net graph must give identical colours; ground, +3.3 V_A, the negative
rail, the reference and the DAC pin are anchored by name.

**Covers:** values and connectivity of 29 scope elements and 14 AWG elements. **Does not cover:** the sources and
strays (by design); the power/calibration block, which has no netlist (checked by `C1..C4` arithmetic instead);
channel-for-channel swaps between the identical scope channels (electrically identical, so not a difference);
pin-to-pin crossings that preserve the graph's symmetry; the models' internals; the AWG capacitor derating (see below).

Recorded differences between the studies and the schematic: the AWG study carries the two 10 uF filter capacitors
as 14 uF effective (0.7 derating, a rule in `RULES`); the scope study has 1.1 uF at the reference output where the
powercal parts put 1 uF there and the 100 nF at the input (both treated as the reference model, not compared).

## Decisions to confirm

1. **ADS1115 allocation (final, from the coordinator).** AIN0 reference, AIN1 the 2/3 ladder tap, AIN2 the sense tap
   through R510 (3.9k), AIN3 the divider's bottom node B through R511 (10k); the differential pair is AIN2 - AIN3.
   My first reading (inputs 1..4 in order) put the pair on AIN1/AIN2, which the multiplexer cannot select; `C3`
   now derives the pair from the netlist and checks it against the multiplexer table.
2. **I2C** is the SAM3X's TWI0 on PWMH0.9/.10 (labelled SDA1/SCL1 on the Due header; no pull-ups there), with two
   4.7k Basic pull-ups (C23162) to +3.3 V_A on the shield.
3. **Calibration jumper `J501`** (powercal's J_RAT, shunt SH_RAT): a 1x3 male header, hand-soldered, silkscreen "CAL" with
   the on position (pins 2-3) marked (layout). Pin 1 = TAP4 (the 2/3 tap, 2.0 V), pin 2 = B, pin 3 = TAP3 (the 1/2 tap,
   1.5 V, the calibration node). A 2.54 mm shunt across 2-3 calibrates; across 1-2 is the one wrong placement; no shunt
   is the default tie. The shunt is a loose hand-fitted part (`design.HAND_FITTED`, `NOT_A_SYMBOL`, checked by `B1`
   and `C4`); the other hand-fitted parts are the BNCs, the stacking headers, J501 and the two M2.5 standoffs (nylon or brass, header-stack height) with DIN 912 M2.5 screws (head 4.5 mm).
   Every Due pin stays reachable from the top.
4. **Part numbers I added** (not in any study): 2 x 4.7k pull-up C23162, 0R C21189 for PA-7 (unfitted), six test
   points, two mounting holes; all Basic per `../jlc-basic.csv`. The BAV99 is drawn with KiCad's
   BAT54S series-pair symbol (pins 1 A1, 2 K2, 3 common), as version 1 did.
5. **TPH2502 pinout** is the datasheet's pin figure (OUTA, -INA, +INA, V- | +INB, -INB, OUTB, V+, standard dual);
   the symbol is one unit, one package. Footprint `SOIC-8_3.9x4.9mm_P1.27mm`; ADS1115 footprint `MSOP-10_3x3mm`
   (KiCad's own ADS1115 symbol names a TSSOP-10 footprint, which is wrong for the DGS package).
6. **The AWG study moved while this was built** (11:03 on 2026-11-12: Rf = Rg2 = 3k, Rbin 2.7k, offset filter
   100R + 2 x 10 uF back, 330 pF output pole gone). The schematic follows the files as read at 11:07, and so did the
   powercal bleed (1.8k, C4177). the checks fail the moment a `parts.csv` or `.cir` moves again, which is its job.
   The AWG's `design.md` still describes the earlier circuit.
7. The BNC footprint's 3D model is a stand-in (as in version 1).
8. **Standoffs `MH601`, `MH602` are M2.5** (not M3), at Due holes (96.52, 2.54) and (90.17, 50.8), footprint
   `MountingHole_2.7mm_M2.5` (KiCad has no DIN 912 footprint: the layout adds a 4.5 mm head keepout). MH602 is inside the
   outline (2.54 mm from the top edge) and 3.81 mm from XIO0 pin 1, which leaves about 0.7 mm to that pad with the 4.5 mm head.
9. The bleed follows `powercal/parts.csv` as it stands (1.8k, C4177); `B1` fails when it moves.
