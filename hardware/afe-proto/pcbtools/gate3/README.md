# pcbtools.gate3: the gate-3 package generator

Regenerates a board's gate-3 package from the board file and the repo: `GATE3.md` and `data/*.json|csv`. Every number comes from the
board (pcbnew arrays, kicad-cli DRC), from `pcbtools.rules`, from the study result files and BOM engine the table names; none is typed in.
Nothing in the engine names a board (`tests/pcbtools/test_no_board_literals.py` scans it): the two inputs below say everything board-specific.

    docker/pcb/run.sh -m 3G -t 900 -c 2 env PYTHONPATH=hardware/afe-proto python3 -B -m pcbtools.gate3 \
        --config v2_layout --table gate3_v2 --out hardware/afe-proto/v2/layout/gate3

Heavy: pcbnew and `kicad-cli` are in the PCB image only (about 18 s on v2). `v2/layout/gate3/build_gate3.sh` is that command with the
v2 names filled in. `--check-table` only checks the table; the CLI exits 2 and prints the field when the table or the config is incomplete.

| flag | meaning |
|---|---|
| `--config NAME` | board config, `pcbtools/boards/NAME.py` (fields in `pcbtools/CONFIG_FIELDS.md`); a file path also works |
| `--table NAME` | gate-3 table, `pcbtools/boards/NAME.py`, or a path |
| `--out DIR` | `GATE3.md` and `data/` are written here and nowhere else |
| `--stamp TEXT` / `GATE3_STAMP` | text of the generated-at time (default: now, to the minute) |

The generated-at line is the only clock input and is injectable, so a run can be reproduced; no file modification time is read (a checkout
does not keep them). The renders' freshness is by content: `pcbtools/gate3/rendersum.py` (run last by `render.sh`) writes `renders.sha256.json`
beside the images, holding the board hash they were made from and each image's hash. `tests/pcbtools/test_gate3_equivalence.py` runs the v2
table against the committed `v2/layout/gate3` with the stamp injected from that package and requires every file to match to the byte (it also breaks a table
entry and an engine rule once each and requires the comparison to fail).

## The two inputs

1. **The board config** (`boards/v2_layout.py`, `boards/v1r.py`): what `pcbtools.rules` reads. The engine also reads `GND`, `BOARD_SETUP`,
   `OVERHANG`, `BOARD_MAX_MM`, `BAND_NAME`, `KEEPOUTS`, every config field the table names as a margin `limit`, a `LR_RENAMES` field, a
   `CFG_QUOTED` field or a `NET_CLASS_FIELDS` field. `table.check_config` lists what a config lacks.
2. **The gate-3 table** (`boards/gate3_v2.py`; `boards/gate3_v1.py` is the v1 template): a module of named fields and no logic. Paths are
   relative to the repository root. A field that holds prose is a *template*: `{name}` is filled by the engine, `{name:n3}` formats a
   number the way the document does (`fnum(x, 3)`), `{name[key]}` indexes a mapping. A value that carries `TODO(` anywhere (inside a list or
   dict too) is an unfilled field: the engine refuses to run and names it. `None` is legal only where said below.

## Table fields

Identity and files

| field | what |
|---|---|
| `TITLE`, `GENERATED_BY` | the heading, and the "generated by" text (the wrapper script as the document should cite it) |
| `BOARD`, `PROJECT` | the `.kicad_pcb` and its `.kicad_pro` |
| `RENDER_DIR`, `RENDERS`, `RENDER_LINK_PREFIX`, `RENDER_HINT` | the renders folder, `(view, file name)` pairs, the folder as `GATE3.md` links it, the re-render command text |
| `DUE_ORIGIN` | KiCad x = ox + x, y = oy - y: the Due-mm frame the document quotes |
| `RULE_DOC` | the rule table (`\| LR-n \| text \|` rows) and the file the cited rows are read from |
| `SECTION_SOURCES` | the rows of "where each section comes from" |

LR table (section 2)

| field | what |
|---|---|
| `LR_HEADING`, `LR_INTRO` | heading, and the paragraph (`{config}` = the config name given on the command line) |
| `LR_DOC_ROWS` | the displayed rule names whose text is looked up in `RULE_DOC` |
| `LR_RENAMES` | `(checker row, label shown, config field filling {})`: v2 shows the checker's `LR-12 DECOUP_MAX` as `LR-4 decoupling (...)` |
| `LR_SUBCHECKS` | `(substring of a displayed name, text)` for sub-check rows that are not in `RULE_DOC` |
| `DRC_ROW` | the name of the row the engine adds from kicad-cli (`LR-10`) |

DRC (section 3)

| field | what |
|---|---|
| `DRC_DOCUMENTED`, `DRC_DOCUMENTED_LABEL`, `DRC_DOCUMENTED_NOTE` | `(violation type, a reference it names)` pairs counted as documented; the label in the count line; the paragraph |
| `RULE_DIFF_TEXT` | paragraph when the project file's rules differ from the config's `BOARD_SETUP` (`{n}` = how many) |

Bridges and hops (section 4)

| field | what |
|---|---|
| `BRIDGE_REF_PATTERN` | `re.fullmatch` pattern of the bridge references on the board |
| `BRIDGES_SOURCE` | `(module, attribute path)` of the design's list of `(ref, net a, net b, block, justification)` tuples (nets without the leading `/`) |
| `NET_CLASS_FIELDS` | how a crossed net is classed, from config fields: `adc` and `divider` are each the union of two fields (`FIELD` or `FIELD.key` for a list of dicts), `vref_prefix` a field of prefixes, `other` the first field minus the second |
| `D24_ROW_PATTERN`, `D24_QUOTE_PATTERN`, `D24_FOUND`, `D24_MISSING` | the cited count sentence: a pattern for its row in `RULE_DOC`, for the quoted sentence inside it, and the text when found (`{quote}`) or not |
| `BRIDGE_ACCEPT` | the acceptance sentence (`{nb} {nover} {over} {parts} {div}`) |

Deviations (section 5)

| field | what |
|---|---|
| `POWER_CAPS` | `dict(ic=, caps=, far_mm=)`: the generator IC and its capacitors, measured pad to pad; the data key is `<ic lower case>_pin` |
| `POWER_CAPS_CAPTION` | caption of that table |
| `CFG_QUOTED` | config fields kept in the run's data (the hop limits are always needed; the waiver tables if the rows below are on) |
| `CFG_FOREIGN_WAIVED`, `CFG_GAP_WAIVED`, `CFG_GAP_MIN`, `CFG_GAP_ONE_LABEL` | config names of the designator waiver tables and thresholds |
| `DEV_COURT`, `DEV_POWER`, `DEV_FOREIGN`, `DEV_GAP`, `DEV_OUTLINE`, `DEV_EDGE`, `DEV_PROOF` | each a `(rule / item, deviation template, status / authority template)` row. `DEV_FOREIGN` and `DEV_GAP` may be `None` (a config with no designator waivers); `DEV_OUTLINE`'s third element is `None` because `MC1_FOUND` / `MC1_MISSING` is the authority |
| `DEV_FOREIGN_EMPTY`, `DEV_PROOF_JOINED`, `DEV_PROOF_NOT` | the alternative texts those rows pick between |
| `MC1_COMMIT`, `MC1_PATTERN`, `MC1_FOUND`, `MC1_MISSING` | the outline ruling: the commit looked up in git (when git exists), the pattern looked for in `RULE_DOC`, the two authority texts |
| `MARGINS` | rows of `dict(rule, what, row, key, limit, kind)` (a checker figure against a config limit; `kind` is `max` or `min`), or `dict(rule, each_of, limit, kind)` for every figure of one checker row |

Connectivity proof (section 5.1)

| field | what |
|---|---|
| `PROOF` | `dict(net, source, pins, upstream, on_net_head, arms)`: the net, the source pad (`REF.PIN`), the pins to prove joined, `(upstream net, pad, pad)`, the zone-table column head, and `(label, pin, 'first' or 'middle')` cut arms (one track cut, graph against DRC). Data keys follow the pins: `path_<ref>_<pin>`, `joined_<pin>`. |
| `PROOF_PATH_ORDER` | the pins in the order their path tables are listed |
| `PROOF_HEADING` ... `PROOF_RULE` | the prose, templates: `{status}`; `{net}`; `{tracks} {length} {vias} {npads} {pads} {arcs} {zones_on_net} {nzones}`; `{ncomp} {net} {pieces} {same} {src} {j_a} {j_b}`; `{ref} {pin} {src}`; `{n} {tracks} {vias} {fills} {chain}` (upstream); `{n}` (DRC) |

Evidence rows (section 6)

| field | what |
|---|---|
| `EVIDENCE_HEADING` | the heading |
| `EVIDENCE_DATA` | `dict(name, json[, values, write])`: a study file by repo path. Without `values` the whole file is `name` in the templates; with `values` (`{key: dotted path}`) only those are read, and are written to `data/<write>` if given |
| `EVIDENCE_DERIVED` (optional) | values computed in order from the above: `find` (a list item matching `match`), `add`, `div`, `margins` (limit minus a value per case), `regex` (a sentence read from a file) |
| `EVIDENCE` | the blocks in order, each `dict(kind=...[, when=name])` (skipped when `when` is absent): `text` (a template), `table` (`head`, `rows` of templates; `id` names it for tests), `cap_table` (`data`: a `pcbtools.cap` converged result), `matrix` (`data`, `head0`, `rows` of `(key, label)`: a study with `results` by case and `cases` notes) |

BOM and cost (section 7)

| field | what |
|---|---|
| `BOM_ENGINE`, `BOM_DATA_DIR`, `BOM_EXTRA_CSV` | the engine module (needs `Data(folder)`, `lines`, `Part`, `tier`, `cost`, `FX`, `D_RATIO`, `PER_ORDER_MAX`; `v2/bom/bom.py` is the reference), its data folder, the owner-parts file as the text names it |
| `BOARD_COUNTS`, `REPORT_BOARDS`, `TARGET_BOARDS` | the board-count tiers priced; the tier of the per-board line column; the two tiers the cost sentence quotes |
| `OWNER_FITTED_LCSC`, `BRIDGE_PART`, `WATCH_PACKAGES` | parts tiered on all boards; the bridge part `dict(lcsc, footprint_prefix)`; packages reported as used or not |
| `BOM_INTRO`, `BOM_UNIT_NOTE`, `BOM_RECONCILE_NOTE`, `BRIDGE_PART_TEXT`, `BOM_PCB_NOTE`, `COST_TARGET`, `COST_TARGET_RESULT`, `GAPS` | the prose and the closing list of gaps |

## What each section reads

| section | reads |
|---|---|
| header | the board file (sha256, time), `git` if present (not in the image) |
| 1 Renders | `RENDER_DIR`: existence and age against the board |
| 2 LR table | `pcbtools.rules.ROWS` on the board with the config; LR-10 from kicad-cli; rule text from `RULE_DOC` |
| 3 DRC | kicad-cli at the project file (run A) and with the config's `BOARD_SETUP` applied to a scratch copy (run B); the board and project file are never touched |
| 4 Bridges and hops | board arrays; `BRIDGES_SOURCE`; `NET_CLASS_FIELDS`; `D24_*` from `RULE_DOC` |
| 5 Deviations | the above, `POWER_CAPS`, the config's waiver tables and outline fields, `MC1_*`, `MARGINS` |
| 5.1 Proof | `connectivity.py`: the copper graph of one net from the board arrays, against DRC, with one-track cuts |
| 6 Evidence | the files in `EVIDENCE_DATA` (read, not recomputed) |
| 7 BOM | the board's `LCSC` properties, the BOM engine and its data folder |

## What is not general

- The prose of a package is the board's own and lives in the table; a v1 table needs its own sentences wherever a template says so.
- The generic text still names the rules by their `docs/afe.md` ids (`LR-1`, the hop method, the `LR-10` courtyard row) and uses the Due-mm
  frame: a board under different rules would need those in the table too.
- The BOM engine contract above is `v2/bom/bom.py`'s, for both boards: v1 runs it over `bom/v1/data/`. `BOM_PATHS` is an optional field (default none): the engine's own `--path` overrides (`scope`, `awg`, `powercal`, `basic`, ...) for a data folder that is not laid out the way `v2/bom/` is.
- The committed v2 `GATE3.md` still says it was generated by `gate3.py` and cites `v2/layout/gate3/connectivity.py`: both are fields of
  the v2 table kept as they were, so the package reproduces to the byte; correct them in the table and regenerate when the file is next rebuilt.
